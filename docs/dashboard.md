# Dashboard — operational reference

> Phase 4 deliverable. Implementation reference for `frontend/`.
> **Canonical design is `spec.md` §9**; ADR-15 (dashboard is the primary
> control plane), ADR-23 (SSE replay/cutover contract the client
> consumes), ADR-25 (run-artifacts second sandboxed root), ADR-26
> (frontend toolchain mandates) carry the rationale. `frontend/README.md`
> is the developer quick-start (how to run the dev server / regenerate
> the client). When this doc disagrees with `spec.md`, `spec.md` wins.

## Shape

A Vue 3 + TypeScript SPA built by Vite, in `frontend/`. It is the
**primary user-facing control plane** (ADR-15) — it starts, inspects,
pauses, and cancels runs and manages projects/prompts, not a read-only
spectator. In prod the built bundle (`frontend/dist/`) is served by
FastAPI same-origin; in dev the Vite server proxies `/api` →
`127.0.0.1:7800`. Single-user localhost MVP — no auth, no router
guards (ADR-12).

Stack: vue-router **v5** + Pinia + Pinia Colada + Vite, TypeScript
strict. The API client is generated, not hand-written.

## Backend contract it consumes

The dashboard is a pure client of the Phase 3 REST surface
(`docs/api.md`, `spec.md` §7) plus the ADR-25 artifacts routes. It adds
**no** backend behavior. Load-bearing contract points:

- **Typed client.** `src/api/schema.d.ts` is generated by
  `openapi-typescript` from the running backend's `/openapi.json`
  (`npm run gen:api`; backend must be up). `src/api/client.ts` wraps it
  with `openapi-fetch`, base = page origin (paths already carry `/api`,
  so dev-proxy and same-origin prod both resolve correctly). The
  generated file is committed; never hand-edit it — regenerate.
- **Preview is project-scoped.** `GET /api/runs/{id}/preview`'s path
  segment is the **project id** (the New-Run wizard previews a run that
  does not exist yet); the prospective prompt goes in `prompt_body` /
  `prompt_id` query params. Side-effect-free — no run row/event/dir.
- **SSE (ADR-23).** `GET /api/events/{run_id}`, SSE `id:` = event
  `seq`. Browsers cannot set the `Last-Event-ID` header on a native
  `EventSource`, so reconnect uses the `?last_event_id=` query fallback
  (api.md/ADR-23 explicitly support it). A finished run streams history
  then cleanly EOFs / 204s; `run_ended` closes the stream. The client
  must **not** reconnect-storm a finished run.
- **File browsers are sandboxed.** Two roots, one audited resolver:
  project files (`/api/projects/{id}/files[...]`) and run artifacts
  (`/api/runs/{id}/artifacts[...]`, ADR-25). Same guards: binary → 415,
  >5 MiB → 413, sandbox violation → 400, absent → 404.

## Layout (`frontend/src/`)

| Path | Role |
|---|---|
| `api/client.ts` | typed `openapi-fetch` client over the generated `schema.d.ts` |
| `api/sse.ts` | `RunEventStream`: owns the `EventSource` lifecycle, `?last_event_id=` resume, stops on the terminal `run_ended` / clean EOF (no reconnect-storm) |
| `lib/queries.ts` | **single source of query keys** + Pinia Colada query/mutation hooks; `keys` factory, `unwrap`/`ApiError`, `asAsyncState`, `useInvalidate`, the `BrowserSource` abstraction |
| `lib/render.ts` | client render pipeline — markdown-it (`html:false`) + lazy shiki + dynamic-import mermaid + diff2html |
| `lib/routes.ts` | vue-router v5, all views lazy-loaded |
| `stores/` | Pinia = **ephemeral UI state only** (selection, toggles, the SSE event stream). Server data lives in Pinia Colada, never duplicated here (spec §9.2) |
| `views/` | `HubView` `/`, `ProjectView` `/projects/:id`, `NewRunWizard` `/projects/:id/new-run`, `RunDetailView` `/runs/:id` |
| `components/` | `runs/` (timeline, iters, artifacts, worktree, pause, wizard steps), `files/` (tree/viewer + render wrappers), `prompts/` (list/editor/versions), `projects/`, `shared/` (StatusBadge, ActionButton, AsyncBoundary) |

## State model (spec §9.2)

- **Pinia Colada** = the REST cache + revalidation. Every server
  read/write goes through a `lib/queries.ts` hook; components never
  call the `api` client directly and never cache server data in a Pinia
  store. Query keys are prefix-nestable (`['runs']` ⊃
  `['runs','detail',id]`); invalidate the broadest affected prefix.
- **Pinia stores** hold only ephemeral UI state. The events store is
  the exception that proves the rule: the SSE event list is a *push
  stream*, not a cacheable REST resource, so it lives in
  `stores/events.ts` (run *detail* still goes through Colada).
- **SSE → cache.** The events store is **run-status-aware**: terminal
  run (`done`/`failed`/`cancelled`) → REST replay via
  `GET /api/runs/{id}/events`, SSE not opened; `running`/`paused`
  (paused is *not* terminal) → live `RunEventStream`. Lifecycle events
  trigger **coalesced** cache invalidations (one `queueMicrotask`
  flush per burst — a fast pi run does not fire hundreds of
  invalidations/sec).

## Replay mode (spec §9.3)

There is no replay-mode toggle. A finished run's SSE endpoint returns
the historical event list and closes; the dashboard renders the same
UI from the static list. Live and historical are treated identically.

## File render pipeline (spec §9.4)

Client-side; the backend serves raw bytes. Markdown → markdown-it
(`html:false`, +footnote/task-list) with ```mermaid fences →
mermaid.js inline SVG and code fences → shiki. Code → shiki. Plain →
monospace. Binary (415) → "binary content (N bytes) — download". Diff
→ diff2html. **One** `FileTree`/`FileViewer` + the `BrowserSource`
abstraction serves both the project Files pane and the run Artifacts
pane (mirrors ADR-25's single-sourced backend — no duplicate
tree/viewer).

## Worktree pane — MVP degradation

The Worktree pane shows read-only `worktree_path` + `branch` from the
run-detail response. Live git status / per-file diff is a deliberate
post-MVP gap (Phase-4 scoping decision; ADR-25/ADR-26) — no git
endpoint, no subprocess surface. The pane is structured so the richer
data slots in later without restructuring.

## Fanout-join dashboard additions (Phase 9e)

Four user-visible pieces landed in 9e:

**Children pane.** `RunDetailView` renders a `ChildrenPane` tab when
`parent_run_id == null` and at least one child run exists. Each row
shows `status · short-id · role · branch · summary` (all available from
`GET /api/runs/{id}/children`). The pane auto-refreshes via SSE: the
events store extends `INVALIDATING_KINDS` with `subagent_dispatch`,
`subagent_return`, and `child_runs_resolved`; receiving any of those
fires a `['runs','children',runId]` Pinia Colada invalidation so the
`useRunChildrenQuery` hook re-fetches.

**Parent chip.** When `parent_run_id != null`, the run-detail header
renders a `ParentRunChip` that links back to the parent's `/runs/:id`
view. Clicking it is a normal vue-router navigation.

**Cascade-aware Cancel button.** The Cancel button is now enabled for
`status ∈ {running, awaiting_children}`. For a parent in
`awaiting_children` the label reads "Cancel run and N children" (N
derived from the children query result length); the cancel API call is
unchanged — `POST /api/runs/{id}/cancel` cascades automatically via the
ADR-37 runtime helper added in 9d.

**"Show child runs" toggle.** The Project view Runs pane hides child
runs by default (they clutter the top-level list). A small toggle sends
`?include_children=true` to `GET /api/runs` when enabled. The MCP tool
`relay__list_runs` always passes `include_children=True` so MCP callers
see the full picture.

## Toolchain mandates (ADR-26 — do not regress)

1. **vue-router v5** (not v4) — adopted directly (`lib/routes.ts`).
2. **shiki** = `createHighlighterCore` (`shiki/core`) +
   `@shikijs/engine-javascript` JS regex engine + per-language grammars
   dynamically `import()`ed — **never** the convenience bundle /
   `getHighlighter` / `bundledLanguages` (`lib/render.ts`).
3. **mermaid** = dynamic `import('mermaid')` on first render only —
   **never** a static top-level import (`lib/render.ts`).
4. **Vite SSE dev-proxy** = long `proxyTimeout` + no buffering for
   `text/event-stream`, or the live tail stalls in dev
   (`vite.config.ts`).
5. **vitest v4 removed the `coverage.all` toggle entirely** — it now
   unconditionally counts every file matched by `coverage.include`.
   Coverage scope is set via `coverage.include` (`vite.config.ts`); a
   literal `coverage.all` is a v4 type error. (The plan's "set it
   explicitly" predates the v4 change — see ADR-26.)
6. Routed views are keyed by `route.fullPath` so a param-only
   navigation remounts (Vue Router otherwise reuses the instance and
   would carry per-run module state / an SSE stream across runs).

## The gate

The project gate is two-sided — Python **and** frontend, both must be
green:

```sh
# Python (from repo root)
uv run ruff check .
uv run mypy
uv run pytest                       # 342 passed, 3 pi-e2e gated (post-14f)

# Frontend (from frontend/)
npm run check                       # eslint --max-warnings 0 + vue-tsc + vitest (186 passed)
npm run build                       # vue-tsc -b && vite build (must also pass)
```

`npm run check` is the composite frontend gate; `eslint` is hardened
with `--max-warnings 0` so a warning fails it. vitest runs under jsdom
with the v8 coverage provider. The eager first-load budget (Phase-4
mandate; <800 KB gz) is met with wide margin; shiki grammars,
mermaid, katex, cytoscape, diff2html, and the markdown render
pipeline are all lazy chunks. Re-measure with `npm run build` after
any new SFC adds a heavy dep.

## Pause-for-review (14a–14f) and the SSE event-kind contract

The dashboard's `PauseAnswerForm.vue` (rendered when a run is
`paused`) reads the latest paused iter's `signal_args.review_paths`
(14f / ADR-41; legacy scalar `review_path` is read as a one-element
list for migration). When the array is non-empty it renders a review
pane above the question/answer block: textarea + lazy markdown
preview, Save button firing `PUT /api/runs/:id/artifacts/{path}`,
`[ Preview | Diff ]` view-mode toggle on the right pane (Diff
disabled while clean; renders dirty-vs-loaded-baseline via the
existing lazy `DiffRender.vue` entry — 14e). N == 1 renders the
single-pane layout byte-identical to 14c; N > 1 renders a tab bar
with per-tab dirty state (14f) — one Save in flight at a time on
the active tab, Resume disabled only while that Save is in flight,
soft-warning surfaced for unsaved changes on non-active tabs (which
do **not** block Resume — an abandoned tab must not strand the
operator). Timeline `artifact_edited` rows are click-targets that
navigate the artifacts pane to the file's *current* on-disk content
(14e — not a historical diff, since ADR-40 §B1 does not preserve
before-content). `UsageRow.vue` (9g) renders `harness_session_ended`
events inline in the timeline with `stop_reason` + summed token
counts (pi-flavoured keys per ADR-18: `input` / `output` /
`cacheRead` / `cacheWrite` / `totalTokens` + `cost.total`).

> **Dual-list invariant (load-bearing — post-9g bug-fix sweep).**
> Every event kind the backend can emit (spec §3.2) MUST appear in
> both `frontend/src/api/sse.ts::KNOWN_EVENT_TYPES` AND
> `frontend/src/stores/events.ts::INVALIDATING_KINDS`. The browser
> `EventSource` only fires listeners for explicitly-registered named
> events — a kind in `INVALIDATING_KINDS` but missing from
> `KNOWN_EVENT_TYPES` is silently dropped on the live SSE stream
> (refresh works because it reads REST replay, masking the bug —
> exactly the regression Bug 3 in CLAUDE.md "post-9g bug-fix sweep"
> caught). Audit both lists against `grep -rn '"kind":\|"kind"=' src/`
> when adding a new event kind. The single vitest setup hook
> (`frontend/tests/setup.ts`) swallows ONLY `ApiError`-shaped
> unhandled rejections from Pinia Colada queries that 4xx on mount
> (commit a9813f1); anything else still fails CI.
